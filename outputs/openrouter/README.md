# BehaviorBench evaluation — `tencent/hy3`

Full-sample run of the BehaviorBench suite against **Tencent Hunyuan 3 (`tencent/hy3`)**
via OpenRouter. Tencent is not in the paper's leaderboard, so this extends coverage to a
previously unrepresented Chinese lab.

**Everything published here is the program's own output.** No metrics were recomputed,
re-averaged, or reformatted by hand.

The repo treats the result JSONs as the leaderboard artifact (`README.md` → *Outputs*:
"Each run writes a timestamped JSON file under `<output-dir>/<model-name>/`"), and
`tencent/hy3/` follows that layout. Everything else on this page is orientation for a human
reader, not a required format.

`RESULTS.txt` is generated by [`show_results.py`](show_results.py), which contains no metric
logic: it rebuilds the program's `EvaluationResult` objects from the saved JSONs and calls
the program's own `.summary()` — the same method `behaviorbench-eval` uses to print to the
console during a run (`src/behaviorbench/eval/main.py:208`).

### The single command

The tool runs one task per invocation. This is the whole thing:

```bash
uv run behaviorbench-eval \
  --task game_behavior_dictator \
  --model-type openai \
  --model-name tencent/hy3 \
  --api-base https://openrouter.ai/api/v1 \
  --concurrency 4 \
  --output-dir outputs/openrouter
```

[`run_full.sh`](run_full.sh) is that command in a loop over all 39 task names, plus retry-on-429
and logging so it could run unattended for ~4 hours. Nothing else.

### Reproduce

```bash
bash outputs/openrouter/run_full.sh                          # ~4h, ~$1.40
uv run python outputs/openrouter/show_results.py             # re-render RESULTS.txt
```

> **Note on the code version.** `--model-type openai` was broken before commit `690c1b6` —
> it built an Azure client pointed at localhost and failed every call. That fix
> ([PR #1](https://github.com/umich-foreseer/behaviorbench_eval/pull/1)) is what made this run
> possible; earlier code cannot reproduce it.

## What's in a result JSON

Each file in [`tencent/hy3/`](tencent/hy3) contains, per sample:

```json
{
  "prompt":            {"system": "...", "user": "You are paired with another player..."},
  "raw_output":        "I would keep $50 and give the other player [$50].",
  "parsed_prediction": 50.0,
  "expected":          null
}
```

plus `metrics` (computed by the program), `metadata` (sample counts, parse failures,
model/human means and standard deviations), `inference_settings`, and `token_usage`.

Every headline number can be traced back to these files.

## Observations

*This section is interpretation, not program output. Every number below is quoted from
[`RESULTS.txt`](RESULTS.txt) — `W` is `Wasserstein_with_ks_distance` from `metrics`; the
mean/SD columns are `model_action_mean` / `model_action_std` / `human_action_mean` /
`human_action_std` from `metadata`. The row marked **mean** is a plain average across the
nine games, and is the only figure computed here.*

hy3 does noticeably better at **predicting** human behaviour than at **reproducing** it.
Prediction tasks land in a normal range (`ieo_economics` accuracy 0.831, `big_five` MAE
~4.8), while the `game_behavior` family — where the model plays the game itself — scores
poorly on distributional fit.

The per-game numbers show why:

| game | model mean | model SD | human mean | human SD | W |
|---|---:|---:|---:|---:|---:|
| bomb | 57.14 | 19.72 | 45.56 | 23.09 | 14.30 |
| dictator | 49.76 | 2.48 | 24.71 | 19.19 | 25.51 |
| guessing | 0.44 | 1.46 | 35.47 | 21.51 | 35.03 |
| public_goods | 9.94 | 0.86 | 8.91 | 6.07 | 24.06 |
| push_pull | 0.07 | 0.25 | 0.57 | 0.50 | 50.30 |
| trust_banker | 75.16 | 6.27 | 55.90 | 37.40 | 22.44 |
| trust_investor | 94.57 | 16.23 | 42.19 | 39.89 | 52.38 |
| ultimatum_proposer | 39.99 | 2.21 | 44.92 | 18.33 | 13.56 |
| ultimatum_responder | 5.57 | 7.13 | 33.29 | 17.80 | 27.81 |
| **mean** | | **6.29** | | **20.42** | |

Two distinct things are going on.

**1. Very low behavioural variance.** Mean model SD is 6.29 against a human 20.42 — roughly
a third of the spread. The dictator game is the clearest case: across 1000 independent
samples of an identical prompt, the model gave **$50 in 98.1% of cases**, with only 5
distinct values and 13 distinct output strings. Humans averaged $24.71 with SD $19.19.

**2. It plays the game-theoretic solution.** Separately from the variance issue, the model's
centre is often displaced toward the rational equilibrium, where humans systematically
deviate — `guessing` 0.44 vs 35.47 (Nash equilibrium is 0), `ultimatum_responder` 5.57 vs
33.29 (accepting tiny offers is rational; humans reject them), `trust_investor` 94.57 vs
42.19. These games are research instruments precisely *because* humans deviate, so added
sampling diversity would not close these gaps — the centre is in the wrong place.

Worth noting: the run used provider-default sampling. How much of point 1 is decoding rather
than the model has not been tested here.

## A note on aggregation

An earlier version of this page reported **family-level averages** (mean MAE per family, etc.).
Those have been removed. The program computes metrics **per task**, and does not aggregate
across separate invocations — so any family average is an added assumption, not program output.

That assumption is not trivial: the raw JSONs carry two MAE variants,
`MAE_with_normalization_mae` (normalised to a common scale) and `..._mae_raw` (each game's
native units). Averaging the raw form across games sums incommensurable units, since
`push_pull` is effectively binary while `trust_banker` runs 0–100+. The choice changes the
acrossgame figure from 22.95 to 30.28.

Rather than pick a convention, this page publishes the per-task numbers as the program
reports them. Aggregate them however the paper does.
